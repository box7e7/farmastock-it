# FarmaStock IT: Self-Contained Windows Application Plan

Goal: install FarmaStock on pharmacy PCs from a single **Setup.exe**. It needs no internet, no Node.js, no Docker and no separate database install. It must work on **one PC** and in a **pharmacy with several counter PCs (banchi) sharing one database** over the local network.

---

## 1. Target environment
| Item | Target |
|---|---|
| OS | Windows 10 22H2 and Windows 11, x64 (ARM64 later) |
| Hardware | 4 GB RAM minimum (8 GB recommended), 2 GB disk free |
| Network | Works fully offline. A LAN is needed only for multi-counter mode. Internet is needed only for future integrations (Sistema TS, wholesalers) and updates |
| Users | Pharmacy staff without IT skills, so the install and updates must be close to one click |
| Peripherals | 2D barcode scanner (USB), receipt/label printer. Fiscal printer (RT) later |

## 2. Deployment modes (one installer, chosen during setup)
```
 MODE A: Single PC                    MODE B: Pharmacy LAN (several counters)
 ┌──────────────────────────┐         ┌───────────────────────────┐
 │ FarmaStock Client (UI)   │         │ MAIN PC ("server")        │
 │        │ http://127.0.0.1│         │  FarmaStock Service ◄──┐  │
 │ FarmaStock Service (API) │         │  SQLite DB + backups   │  │
 │ SQLite DB + backups      │         │  Client (UI) ──────────┘  │
 └──────────────────────────┘         └────────────▲──────────────┘
                                                   │ LAN :47400
                                   ┌───────────────┴───────────────┐
                                   │ Counter PC 2 · Counter PC 3   │
                                   │ FarmaStock Client only        │
                                   └───────────────────────────────┘
```
- **FarmaStock Service**: the existing Fastify API and the built web UI. It runs as a **Windows Service**, starts at boot without anyone logged in, and owns the SQLite database.
- **FarmaStock Client**: a desktop shell (window, taskbar icon, printing, hardware access) that opens the service's UI, either locally or on the main PC.
- The default port changes to **47400**, configurable. Port 4000 is too common.

## 3. Recommended technology
| Concern | Choice | Why |
|---|---|---|
| Desktop shell | **Electron** (electron-builder) | Reuses the React UI unchanged. Mature Windows printing, a kiosk mode, auto-update and access to serial/USB devices. Tauri is smaller but would need a Node sidecar and more Rust glue |
| Server runtime | Official **portable `node.exe` (Node 22 LTS)** shipped inside the app, running a single **esbuild-bundled `server.mjs`** | No Node install for the user. No `tsx` at runtime. The service stays independent of the UI |
| Windows Service | **WinSW** (MIT-licensed, a small exe plus an XML config) | Install, uninstall, auto-restart on crash and log rotation, all controlled from the installer |
| Database | **SQLite** (keep Prisma 6) with WAL mode, in `%ProgramData%\FarmaStock\data\farmastock.db` | Zero administration, a single file that is easy to back up. Prisma's Windows engine (`binaryTargets = ["native","windows"]`) is shipped as an unpacked file |
| Migrations | Embedded **SQL migration runner** (migrations generated by `prisma migrate diff` at build time, applied at service start, tracked in a `_migrations` table) | The Prisma CLI isn't shipped. Upgrades are safe and automatic |
| Installer | **NSIS** through electron-builder, with custom pages: mode A/B, data folder, port. MSI (WiX) is optional later for chains with central IT | Familiar, supports per-machine install, and can run the service and firewall setup steps |
| Updates | **electron-updater** with a release feed, **plus an offline update `.exe`** (USB) | Some pharmacies restrict internet access |
| Code signing | **Authenticode** certificate (OV/EV or Azure Trusted Signing) | Prevents Windows SmartScreen "unknown publisher" warnings. Required for a professional product |
| Build | **GitHub Actions `windows-latest`** runner (the Mac can't produce the Windows Prisma engine and signed installer reliably) | Repeatable signed builds |

> Alternative "portable demo" (2–3 days): a ZIP with `node.exe`, `server.mjs` and a `Start FarmaStock.bat` that opens the default browser at `http://localhost:47400`. Useful for showing the MVP on any Windows PC before the full installer exists. It has no service, no updates and no signing.

## 4. Changes required in the current codebase
| # | Change | Where |
|---|---|---|
| C1 | Central config: `PORT`, `HOST` (127.0.0.1 in mode A, 0.0.0.0 in mode B), `DATA_DIR`, `JWT_SECRET` (random, generated at install and stored in `DATA_DIR\config.json`) | `api/src/config.ts` (new) and `index.ts` |
| C2 | Build step: bundle the API with esbuild into `dist/server.mjs`. Copy `web/dist` and the Prisma Windows engine | `api/build.mjs` (new) |
| C3 | Prisma: `binaryTargets`, a datasource URL built from `DATA_DIR`, SQLite WAL and busy-timeout settings at startup | `schema.prisma`, `stock.ts` |
| C4 | Replace `db push` with versioned migrations and the runtime migration runner. **Back up automatically before every migration** | `api/prisma/migrations/`, `api/src/migrate.ts` |
| C5 | **First-run wizard** instead of demo seed: pharmacy name, VAT number, ASL code, stores/warehouse, admin user. Demo data becomes an optional "Load demo" button | new `/setup` route and page |
| C6 | Production build hides the demo credentials on the login page. Password policy, plus a lockout after failed attempts | `Login.tsx`, auth route |
| C7 | **Backup and restore**: a scheduled daily backup (SQLite online backup API) to `DATA_DIR\backups` with 30-day retention, an optional second copy to USB or a NAS folder, and a restore tool in Settings | `api/src/backup.ts`, Settings page |
| C8 | **Scanner robustness on Windows**: keyboard-wedge scanners often drop or change the GS1 separator (GS / FNC1). Accept a configurable substitute (e.g. `|` or `~`), detect AIs heuristically, and provide a "scanner test" page | `gs1.ts`, new Settings → Scanner page |
| C9 | Printing: an 80 mm receipt and shelf labels through Electron `webContents.print` (silent print to a chosen printer). An ESC/POS raw driver later. The fiscal RT stays a later-phase item | client shell plus print templates |
| C10 | Health and diagnostics endpoint, file logs with rotation in `%ProgramData%\FarmaStock\logs`, and an "export diagnostics ZIP" button for support | API + Settings |
| C11 | Client configuration: the server URL (auto-discovery on the LAN via mDNS or UDP broadcast, with manual IP entry as fallback) and the counter name (per-counter numbering and logs) | Electron main process |
| C12 | Licensing: a signed licence file with offline activation (licence bound to pharmacy name and VAT number, number of counters) and a trial mode | `api/src/license.ts` |

```
  backups\farmastock-YYYYMMDD.db
  logs\

```

## 6. Installer behaviour
1. Pick the mode: **Single PC** / **Main PC (server)** / **Counter PC (client only)**.
2. Main or single PC: install the service and start it automatically. In mode B, add a Windows Firewall rule for TCP 47400 on the *Private* profile only.
3. Counter PC: search the LAN for the main PC, or let the user enter its IP. Test the connection.
4. Create desktop and Start menu shortcuts, register the uninstaller.
5. Uninstall removes the program and service but **keeps `ProgramData` data** unless the user explicitly ticks "delete data", after a backup prompt.
6. Upgrade: stop the service → back up the DB → replace the files → start the service, which runs migrations → health check. **Automatic rollback** to the previous version and backup if the health check fails.

## 7. Security and compliance (health data, GDPR)
- The service listens on 127.0.0.1 in single-PC mode, and on the LAN (Private profile only) in multi-counter mode. **Optional HTTPS on the LAN** with a locally generated certificate trusted by the clients
- The data folder is restricted by ACLs. **BitLocker recommended** (shown in the setup checklist). SQLCipher encryption of the DB is a later option if required
- Per-user login at each counter, automatic screen lock after inactivity, and an audit log of sensitive actions (already partly provided by the immutable movement ledger)
- Backups are encrypted (AES-256 ZIP or similar) when written to external media
- Signed binaries, signed updates, no telemetry without consent

## 9. Test matrix
| Area | Cases |
|---|---|
| OS | Windows 10 22H2, Windows 11 23H2/24H2, standard user vs admin, Italian locale/keyboard |
| Install | Fresh install in each mode, upgrade from N-1 with migrations, rollback on failed migration, uninstall keeping/removing data |
| Resilience | Power loss during a sale (WAL recovery), service crash and auto-restart, main PC offline (counters show a clear error and retry) |
| LAN | 3 counters selling the same product at once (no negative stock, consistent FEFO), discovery on a different subnet (manual IP) |
| Hardware | Scanners: Datalogic, Zebra, Honeywell in keyboard-wedge mode with a GS substitute. 80 mm thermal printer, label printer |
| Data | Daily backup created, restore onto a new PC, backup to USB |

## 10. Risks
| Risk | Mitigation |
|---|---|
| Antivirus false positives on an unsigned `node.exe` or service | Code-sign everything. Submit to Microsoft Defender for analysis before release |
| SQLite concurrency with many counters | WAL plus a short busy timeout. All writes go through the single service (clients never open the DB file). Move to an embedded PostgreSQL only if more than about 10 counters are needed |
| Scanners lose the GS1 separator | Configurable substitute character, AI heuristics, scanner setup barcodes printed in the user guide |
| Prisma native engine packaging problems | Build on Windows CI and smoke-test the packaged app. Fallback: switch to `better-sqlite3` plus a lightweight query layer |
| Users run the app without backups | Backups on by default, a warning banner if the last backup is older than 48 h |
| Chain (several stores) needs central data | Later phase: optional sync service from each store to a central server (outbox/inbox), keeping each pharmacy fully functional offline |
